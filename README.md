# Polar Penguin

Google Drive의 단일 `Input` 폴더와 단일 운영 Spreadsheet로 주문·재고·피킹을 자동 처리하는 Google Apps Script입니다.

## 설치

Apps Script 편집기에서 ROOT로 사용할 빈 Drive 폴더를 지정한 뒤 설치합니다.

```javascript
setRootFolder('ROOT_FOLDER_URL_OR_ID');
setupSystem();
```

설치는 기존 운영 데이터와 사용자 설정값을 유지하면서 누락된 표준 리소스, 헤더, Validation, 서식, 대시보드, 안내, 트리거를 복구합니다. 기존 버전이 만든 레거시 리소스는 자동 삭제하지 않지만 더 이상 사용하거나 새로 만들지 않습니다.

새 ROOT의 구조는 정확히 다음과 같습니다.

```text
ROOT/
├── Polar Penguin
├── Input/
├── Success/
├── Error/
└── Output/
```

`Polar Penguin`은 유일한 운영 Spreadsheet이며 다음 탭을 가집니다.

```text
📖 안내
📊 대시보드
상품마스터
주문(완료)
피킹(라인)
피킹(헤더)
재고이동로그
작업로그
입력처리로그
설정
```

`피킹(헤더)`, `재고이동로그`, `작업로그`, `입력처리로그`, `설정`은 내부 탭이라 기본적으로 숨깁니다. `주문(완료)`은 모든 주문 상태의 원본이며 별도의 예약대기·주문반려·현황 탭은 만들지 않습니다.

## 일상 운영

1. 주문 또는 재고 파일을 `Input`에 넣습니다.
2. 시스템이 헤더로 파일 유형을 판별하고 자동 처리합니다.
3. `Output/YYYY-MM-DD/<피킹지시번호>.pdf`로 피킹합니다.
4. `피킹(라인)`에 `O` 또는 `X`와 필요한 예외사유를 입력합니다.
5. 시스템이 결과와 대시보드를 자동 반영합니다.

파일명으로 주문/재고를 구분할 필요가 없습니다. 여러 파일이 있으면 재고 파일을 먼저 처리합니다.

### 주문 입력

```text
Input → 검증 → S2 주문 취입 → S3 주문 확정
      → S4 피킹지시 생성 → S9 PDF 생성 → Success/YYYY-MM-DD
      → 대시보드 갱신
```

### 재고 입력

```text
Input → 검증 → S1 재고 동기화 → S3 예약대기 재평가
      → S4 신규 확정 주문 피킹지시 → S9 PDF 생성 → Success/YYYY-MM-DD
      → 대시보드 갱신
```

S1~S4는 삭제하지 않은 내부 도메인 서비스입니다. 정상 운영에서는 메뉴로 직접 실행하지 않으며 `processInput()`이 순서대로 호출합니다.

실패 파일은 삭제하지 않고 `Error/YYYY-MM-DD`로 이동합니다. 오류 코드와 메시지는 입력처리로그·작업로그에 남고, `알림이메일`이 설정되어 있으면 Gmail 알림을 보냅니다.

## 작업 결과

- `O`: 실제수량을 필요수량으로 기록하고 예약재고를 소비해 라인을 완료합니다.
- `X`: 부분 출고하지 않고 주문 전체를 취소합니다. 예약재고를 해제하고 이미 차감된 수량은 필요한 경우 복원합니다.

`syncAndRefresh` 트리거가 결과 반영과 대시보드 갱신을 수행합니다. 즉시 반영이 필요하면 메뉴의 `피킹 결과 지금 반영`을 사용할 수 있습니다.

## 운영 메뉴

`📦 Polar Penguin` 메뉴는 다음 작업만 제공합니다.

- `📥 Input` → `Input 지금 처리`
- `📄 작업` → `작업지시서 조회/재출력`, `피킹 결과 지금 반영`
- `📊 운영` → `대시보드 갱신`, `예약대기 현황`, `시스템 상태 확인`
- `⚙ 관리` → `시스템 설치/복구`, `설정 캐시 초기화`, `로그 정리`

예약대기는 `주문(완료)`의 `주문상태=예약대기`로 유지하며 대시보드와 조회 대화상자에서 확인합니다.

## 설정

설치가 관리하는 폴더 값은 다음 네 개입니다.

- `통합Input폴더ID`
- `Success폴더ID`
- `Error폴더ID`
- `Output폴더ID`

`폴링주기(분)`, `지시번호접두어`, `예약키워드`, `재고경고임계치`, `추가투입임계(분)`, `알림이메일`, 열 별칭은 사용자가 변경할 수 있으며 설치 재실행이 유효한 값을 덮어쓰지 않습니다.

## 중복과 동시 실행 보호

- 성공한 Input 내용의 SHA-256 체크섬으로 같은 파일 내용의 재처리를 막습니다.
- `품목별 주문번호`로 주문 라인 중복을 막습니다.
- 피킹지시번호별 PDF가 이미 있으면 기존 파일을 재사용합니다.
- Script Lock과 중첩 호출 깊이로 S1~S5의 동시·중복 실행을 직렬화합니다.
- `setupSystem()`은 `processInput`, `syncAndRefresh`, `onOpen` 트리거를 역할별 하나만 유지합니다.

## 개발 검증

```bash
npm test
npm run lint
git diff --check
clasp status
```

`clasp status`에는 `src/` 아래 Apps Script 런타임 파일과 `src/appsscript.json`만 표시되어야 합니다. `.clasp.json`의 Script ID는 변경하지 않습니다.
