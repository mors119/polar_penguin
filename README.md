# Polar Penguin

Google Drive의 `Input`을 감시해 주문·재고 파일을 자동 처리하고 `Output`에 피킹 PDF를 만드는 Google Apps Script 창고 워크플로입니다.

## 운영 흐름

정상 주문은 다음 순서로 끝까지 자동 처리됩니다.

1. 주문/재고 파일을 `Input`에 넣습니다.
2. 시스템이 유형 판별, 검증, 주문 취입 또는 재고 동기화를 실행합니다.
3. 일반 주문은 전체 주문 재고를 확인해 한 번만 예약하고 피킹 헤더·라인과 PDF를 만듭니다.
4. PDF까지 성공하면 주문 상태가 `처리완료`가 되고 원본은 `Success/YYYY-MM-DD`로 이동합니다.
5. 작업자는 `피킹(라인)`에서 `O` 또는 `X`와, X일 때 예외사유만 입력합니다.
6. 트리거가 주문 단위로 결과를 자동 반영합니다. 모든 라인이 O면 `출고완료`, 하나라도 X면 전체 주문 `취소`입니다.

예약은 입력 실패가 아닙니다. 재고가 부족하거나 예약상품인 주문은 재고를 잡거나 피킹 데이터를 만들지 않고 `예약`으로 저장되며 원본 파일은 Success로 이동합니다. 재고 입고 후 대시보드의 출고 가능 여부를 보고 운영자가 주문을 선택해 `예약 주문 피킹서 생성`을 실행해야 release됩니다.

## 네 가지 주문 상태

- `처리완료`: 재고 예약, 피킹 데이터, PDF가 모두 준비되어 창고 작업 가능
- `예약`: 유효하지만 아직 창고로 release하지 않은 주문
- `출고완료`: 모든 피킹 라인의 O가 확인되고 예약재고가 한 번만 소진됨
- `취소`: 주문 전체 취소와 필요한 재고 복원이 완료됨

## 운영자 화면

기본 표시 탭은 `📖 안내`, `📊 대시보드`, `상품마스터`, `주문(완료)`, `피킹(라인)`입니다. `피킹(헤더)`, `재고이동로그`, `작업로그`, `입력처리로그`, `설정`은 감사·복구·중복 방지에 필요한 내부 탭이라 유지하되 기본으로 숨깁니다. 별도의 예약/주문/재고/피킹 현황 탭은 만들지 않습니다.

`상품마스터`의 상품 정보와 재고 값은 자동 관리됩니다. `기본보관위치`와 `창고메모`는 창고 소유 필드로, 재고 동기화가 덮어쓰지 않습니다. `주문(완료)`의 상태·지시번호·처리 시각은 시스템 관리 필드이고 `운영메모`만 사람이 자유롭게 기록합니다. `피킹(라인)`은 O/X와 예외사유만 입력하는 것이 원칙이며 담당자는 숨겨진 피킹 헤더에 한 번 입력하면 라인으로 전파됩니다.

## 메뉴

- `📥 Input` → `Input 지금 처리`
- `📋 주문` → `선택 주문 취소`, `예약 주문 피킹서 생성`
- `📄 피킹` → `작업지시서 조회/재출력`, `피킹 결과 지금 반영`
- `📊 운영` → `대시보드 갱신`, `시스템 상태 확인`
- `⚙ 관리` → `시스템 설치/복구`, `설정 보기`, `로그 정리`

S1~S4는 메뉴가 아니라 S6 자동 오케스트레이션이 호출하는 내부 서비스입니다.

## 취소와 PDF 복구

취소는 `cancelOrder_` 한 경로만 사용합니다. 예약 주문은 재고 변동 없이 취소하고, 처리완료 주문은 예약재고를 가용재고로 되돌립니다. 출고완료 주문은 실제 상품 반환 경고에 명시적으로 동의한 경우에만 실제 출고 수량을 가용재고로 복원합니다. 이미 취소된 주문은 아무 재고도 다시 움직이지 않습니다.

PDF 생성이 실패하면 주문을 처리완료로 표시하지 않고 피킹 헤더를 `출력오류`로 남깁니다. `작업지시서 조회/재출력`에서 같은 피킹지시번호를 조회하면 기존 PDF를 재사용하거나 누락 PDF만 재생성합니다. 이 과정은 재고를 다시 예약하거나 피킹 행을 복제하지 않습니다.

## 설치와 설정

`setRootFolder(folderUrlOrId)` 후 `setupSystem()`을 실행합니다. 재실행은 기존 데이터와 사용자 설정을 보존하면서 누락 리소스와 서식, validation, 트리거를 복구합니다.

설정의 폴더 ID와 운영 Spreadsheet ID는 시스템 관리 값입니다. `폴링주기(분)`, `지시번호접두어`, `예약키워드`, `재고경고임계치`, `알림이메일`, 별칭은 사용자 관리 값이며 설치 재실행이 유효한 값을 덮어쓰지 않습니다.

필요 트리거는 `processInput`, `syncAndRefresh`, `onOpen`입니다. 앞의 두 트리거는 각각 입력 처리와 피킹 결과 반영이라는 서로 다른 책임을 가지며, 각 handler는 중복 없이 하나만 유지됩니다.
